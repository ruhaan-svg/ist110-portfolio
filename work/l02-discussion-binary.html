L02 Binary statement

Lesson 2, History and Basics. Discussion, posted 10 September 2026.

The prompt

Translate three binary strings into text with an ASCII table, post the results and compare them with classmates' translations.

My post

  • Hello
  • This is a binary code
  • I love data

I decoded these by hand first rather than using a converter, because I wanted to see the structure rather than just the output. Each 8-bit byte is a place-value sum of 128, 64, 32, 16, 8, 4, 2, 1, so 01001000 is 64 + 8 = 72, which maps to H in ASCII. I cross-checked the full set with an ASCII table afterwards.

Two things stood out. First, the space character 00100000 appears so often that you can break a long string into words before decoding a single letter, which made string 2 much faster than string 1. Second, the last two bytes of string 3 are 00001010, decimal 10, which isn't a letter at all. It's the line feed control character. That was the one point where I nearly went wrong, and it made the bigger idea click: ASCII doesn't only encode what you can see on screen, it also encodes formatting and control instructions. Everything a computer stores, from letters to line breaks to the structure of a file, is the same 1s and 0s. The meaning comes entirely from the encoding standard both sides agree to use.

My replies to classmates

To a classmate who found the similar-looking codes confusing

Same three, so we match. The similar-looking codes tripped me up too, and there's a reason: consecutive letters only differ in the last few bits, and upper and lower case of the same letter differ by exactly one bit (01000001 is A, 01100001 is a). So a single misread digit puts you a letter or a case off.

Small thing, each 8-digit group is a byte, made up of 8 bits. Liked your last point about presence or absence of one thing scaling up to all of this.

To a classmate who decoded each byte in two halves

Same three for me, so we're consistent. Your half-and-half trick makes sense: the first four bits narrow you to a block of the table and the last four pick the character, so you're not holding all eight in your head.

On the last one, 00001010 is 10 in decimal, which is the line feed character, so it's just two blank lines. Anything under 32 in ASCII is a control character rather than something printable, which I thought was the neatest part of this.
