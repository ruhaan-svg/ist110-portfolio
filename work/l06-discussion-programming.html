L06 Programming languages

Lesson 6, Programming Languages. Discussion, posted 7 October 2026.

The prompt

Compare machine, assembly and high-level languages through two of several angles. I chose how hard each is to learn and the role each plays in software today.

My post

Prompt 5: Learning Curve

Machine language is the hardest of the three to learn, because it's pure 0s and 1s and you have to keep track of every memory address yourself. Assembly is easier since instructions get readable names like Add M[4], M[5], M[6], and high-level languages like Python read close to plain English, which is why intro courses start there. Even Python has a learning curve, though: in this week's activity my first run failed with an IndentationError because pasting my code had added extra spaces to every line. The upside is that Python's error messages point you straight to the problem line, whereas a mistake in machine code just quietly gives you the wrong result. Resources follow the same pattern, with W3Schools and free courses everywhere for Python but mostly processor manuals and specialist tutorials for assembly.

Prompt 6: Role in Modern Software Development

Almost nobody writes machine code by hand any more, but assembly is still essential in niches like device drivers, embedded systems and performance-critical code. In 2024, developers of FFmpeg, the open-source video tool behind a lot of streaming software, hand-wrote assembly for one video-filtering function and measured it running up to 94 times faster than the plain C version (Tom's Hardware, 2024). That figure only applies to one function, but it shows why some teams still drop down to assembly when speed really matters. Almost everything else is now built with high-level languages, and Python was number one on the TIOBE Index in June 2026 with a rating of nearly 19% (TechRepublic, 2026). The trade-off is less control over the hardware in exchange for faster development, which usually makes sense because developer time costs more than processor time.

My replies to classmates

To a classmate who explained that high-level languages need translating

Your point that high-level languages have to be translated before the computer can run them was a good one to include. There are actually two ways that translation happens: compiled languages like C translate the whole program into machine code ahead of time, while Python is translated as it runs. I noticed this in our Python activity, because the missing-colon error stopped the program before a single line ran, as Python checks the whole file before it starts. That extra translation step is part of why Python is usually slower than C. Do you think that speed difference matters for most everyday programs, or only for things like games and video?

To a classmate who summed up the trade-off between ease and control

I liked your point that the higher the level, the easier it is to use but the less control you get, because it sums up the whole topic in one line. One thing I'd add is that C++ sits somewhere in the middle: it's high-level, but it still lets you manage memory yourself, which is why it's used so much for games and other software where speed matters. Your point about assembly and operating systems also ties in with something I found. FFmpeg's developers recently hand-wrote assembly for one function and got it running up to 94 times faster than the C version. Do you think AI coding tools will make low-level languages more or less relevant in the future?
